# СБОРКА · BPmanager × CDP-transport

Один репозиторий → один запуск (`start.bat`) → редактор бизнес-процессов **BPmanager**
исполняет нарисованный граф через **существующий CDP-transport** и реальный **Qwen Web**.

Ключевое требование правки ТЗ выполнено: **никакого HTTP-API**. Промпт и ответ ходят
между исполнителем и CDP-transport через **Windows Named Pipe** — только оперативная
память, **ничего не пишется на SSD**.

---

## Как это устроено

```
[Браузер: редактор BPmanager]           (рисует граф nodes + edges, кнопка ИСПОЛНИТЬ)
        │  WebSocket /sborka  — канал редактора (граф → узел, статусы/итоги → UI)
        ▼
[host/sborka-host.mjs — локальный узел]  (раздаёт редактор + ИСПОЛНЯЕТ граф)
        │  исполняет nodes/edges: разветвление, сведение, циклы, MAX_STEPS=1000
        │  промпт = входящие результаты + содержимое ноды
        │  Named Pipe \\.\pipe\SborkaQwen   ← ОЗУ, без файлов, без HTTP
        ▼
[ipc/qwen-ipc-adapter.mjs — минимальный IPC-адаптер]
        │  читает строку из Named Pipe → вызывает СУЩЕСТВУЮЩИЙ Provider_Qwen.ps1
        │  → пишет ответ обратно в Named Pipe
        ▼
[CDP-transport/Provider_Qwen.ps1]  (НЕ изменён: «получил текст → в Qwen → вернул текст»)
        ▼
[Chrome CDP :9222] → [Qwen Web] → ответ тем же путём обратно
```

* **Транспорт Qwen** (узел ↔ адаптер) — **Named Pipe**, данные в ОЗУ. Никаких файлов, HTTP,
  REST, WebSocket, БД, Redis, очередей на этом участке нет.
* **Провайдер не переписан.** `Provider_Qwen.ps1` по-прежнему делает свою работу через
  `CDP_Core.ps1` и вкладку `chat.qwen.ai` (порт 9222). Адаптер лишь передаёт ему входную
  строку (через stdin, чтобы не было ограничений командной строки) и забирает ответ (stdout).
* **Исполнитель графа** работает с существующей моделью `nodes + edges`:
  - `A → B → C` — цепочка;
  - разветвление: результат `A` уходит и в `B`, и в `C`;
  - сведение: `D` исполняется после результатов **всех** входящих (`B` и `C`), в промпт `D`
    передаются результаты всех входящих нод;
  - циклы разрешены, повторный вход исполняет ноду заново; аварийный предел `MAX_STEPS = 1000`.

## Запуск

1. Убедитесь, что запущен Chrome с открытой вкладкой **chat.qwen.ai** и включённым
   удалённым портом отладки **9222** (это уже сделано, к браузеру вопросов нет).
2. Дважды кликните **`start.bat`** в корне репозитория.

`start.bat` поднимает IPC-адаптер и локальный узел, затем открывает редактор:
`http://127.0.0.1:4398`. Дальше: рисуем схему → **ИСПОЛНИТЬ**.

Ничего устанавливать/настраивать не нужно: узел и адаптер используют только встроенные
модули Node.js (без `npm install`), CDP-transport работает на встроенном в Windows
PowerShell. Единственное внешнее требование — сам Node.js, который уже необходим BPmanager.

## Структура репозитория

```
СБОРКА/
├── start.bat                    ← единственный запуск
├── host/sborka-host.mjs         ← локальный узел: редактор + исполнитель + клиент Named Pipe
├── ipc/qwen-ipc-adapter.mjs     ← минимальный IPC-адаптер: Named Pipe ↔ Provider_Qwen
├── CDP-transport/
│   ├── Provider_Qwen.ps1        ← существующий провайдер Qwen (без изменений)
│   └── CDP_Core.ps1             ← существующее ядро CDP
├── src/ … index.html, dist/     ← редактор BPmanager (React, собирается в dist/)
└── README.md
```

Редактор BPmanager размещён в корне репозитория (так устроена его сборка Vite); после
`npm run build` он попадает в `dist/`, который и раздаёт локальный узел. Всё остальное —
папки `CDP-transport/`, `ipc/`, `host/` и `start.bat`.

## Что убрано по сравнению с прежней версией

- Нет эндпоинтов `/api/qwen`, `/api/health`, `/api/execute` — и вообще никакого HTTP-API.
- Браузер не делает ни одного `fetch(...)`: транспорт редактора — WebSocket до своего узла,
  хранение графа — localStorage.
- Промпт/ответ не пишутся на диск — только Named Pipe (ОЗУ) и stdin/stdout провайдера.

## Готовность (по ТЗ)

```
Chrome запущен → start.bat → BPmanager → рисуем граф → ИСПОЛНИТЬ
→ промпт из ноды → \\.\pipe\SborkaQwen → существующий Provider_Qwen
→ Qwen Web через CDP → ответ → \\.\pipe\SborkaQwen → следующая нода
```

Ни один промежуточный промпт или ответ не записывается на SSD.
